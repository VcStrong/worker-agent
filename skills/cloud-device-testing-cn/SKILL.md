# 移动端云真机自动化（国内：WeTest / 阿里云 EMAS）

当前版本：均为 SaaS 持续发布。WeTest（腾讯）官方称云端 1000+ 款 iOS / Android 真机，支持 Appium、Espresso、XCTest / XCUITest 等框架；阿里云 EMAS 移动测试提供云真机、兼容性测试与专家测试服务。
判断理由：国内机型（含各厂商定制 ROM、鸿蒙设备）覆盖好、境内机房、可对接 CI，国内定「采用」；海外机型覆盖与数据驻留不占优，海外定「评估」，默认用 cloud-device-testing-global。图谱 Q-01 原有「云真机」。

## 什么时候用
- 发版前兼容性测试：主流品牌 × 系统版本 × 分辨率矩阵。
- 自动化回归需要在真机上跑（Appium / Espresso / XCUITest 脚本）。
- 复现线上用户反馈的特定机型问题（远程真机调试）。

## 关键做法
- 用线上统计（埋点 / 崩溃平台）的机型分布选 Top 机型，覆盖 80% 以上活跃用户，再加最低支持系统版本。
- CI 集成：构建产物自动上传，触发冒烟脚本，结果回写到流水线与测试管理平台。
- 兼容性测试关注：安装 / 启动 / 崩溃 / ANR / 页面错位 / 权限弹窗 / 厂商推送通道。
- 鸿蒙 HarmonyOS NEXT 应用确认平台是否有对应真机与框架支持，再纳入矩阵。
- 失败用例保留截图、录屏、logcat / 系统日志，直接附到缺陷单。

## 常见坑
- 云真机共享设备，状态残留（账号、权限、缓存）会干扰结果；每次任务前清数据。
- 按机时计费，全量矩阵每次都跑成本高；PR 跑小矩阵，发版跑大矩阵。
- 测试包含真实用户数据或生产密钥，上传第三方平台有泄露风险，用测试环境包。

## 迁移
- 从「自建手机墙」迁移：长期高频机型可保留自建，长尾机型改用云真机。

## 最佳做法
- 合规：上传的测试包应为测试环境构建，不含真实个人信息；企业对数据有要求时选私有化 / 专有云方案。
- 风险与回退：平台故障时，降级为自建设备 + 本地 Appium 跑冒烟。
