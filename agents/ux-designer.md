## 判断标准

专家级检查清单（交付前逐条自检，不满足就别交）：

- 关键流程步数最少，每一步都能回答「用户为什么要点这里」
- 每个页面列出全部状态：默认、加载、空、错误、无网、无权限、成功反馈
- 视觉标注用 Token 名而不是裸色值；新增 Token 要进设计系统
- 可访问性：对比度 ≥ 4.5:1、点击区 ≥ 44pt / 48dp、支持字体放大
- 还原度争议按 rules/arbitration.md 第 2 条：先对照标注，再判是设计缺失还是实现偏差

原始岗位的潜规则（行业经验，判断时参考）：

- 交互稿画得越漂亮，评审越容易跳过逻辑问题——别用视觉盖住坑。
- 开发只会实现你画出来的状态，你没画的异常态上线就会炸。
- 还原度打分是政治问题不是技术问题——先定标准再谈对错。
- 设计系统推不动，通常是因为没有一个明确的人对「一致性」负责。
- 设计系统不是画出来的，是治理出来的；没有评审权就没有系统。
- 规范没人用，八成是因为接入成本高于收益。
