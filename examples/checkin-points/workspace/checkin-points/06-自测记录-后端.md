## 实现说明 <!-- 必填 -->
- **按契约实现**：4 个接口的路径、字段、错误码、外壳与方案一致；已签格子取记录实际值（R5），未签取当前规则；`X-Request-Id` 必须是 UUID（存小写）；`limit` 1–50，默认 20；`next_cursor` 无更多时为 `null`；空流水返回 `[]`。
- **判日**：`clock.Today()` 把任意时区时间转 UTC+8 取日期；跨零点测试覆盖 23:59:59.999 与 00:00:00，以及 UTC 表示的 16:00。
- **幂等与并发**：同一用户的写事务由内存实现的 `txMu`（对应 PG 的账户行锁）串行化；顺序是先按 request_id 重放（含跨零点），再按当天查 `already_checked_in`，再算连签并写记录、流水、余额；撞 `ErrConflict` 时整笔重试一次走重放 / already 分支。
- **限流**：只对 POST /checkin，在 auth 之后，按 user_id；通过 `RATE_LIMIT_ENABLED=false` 关闭。403（受限账号）发生在限流之后，会占用额度。
- **未知 `X-User-Status`**：契约只定义 active / banned / deactivating；实现里「非 active 且非空」一律按受限处理（失败即安全）。
- **提交后埋点**：事务提交成功才打事件；`already` 与重放不打。
- **与方案的差异（均不影响 HTTP 契约）**：
  1. 内部接口 `store.UserTx` 比方案多一个 `LedgerByBiz(bizType, bizID)`，用来在重放 / already 时返回当天发放明细（方案第 4、5 步要求返回，但接口草案没给取数方法）。需要架构师在 Code Review 时确认。
  2. 方案提到的 `/metrics`（expvar 计数）本次**没有做**，属 08 之前的补项（见遗留）。
  3. `civil.Date` 放在 `internal/civil` 包，与方案「internal 包里自己定义」一致。
